## Critical

### C-1 — AoN claim could inflate sum with foreign P2SH *(FIXED)*
- **Was:** `claim` only checked P2SH length + `sum(inputs) ≥ goal`.
- **Fix:** On-chain prefix/suffix redeem equality (`OpTxInputScriptSigSubstr`); only `backerPkh` may differ. TN10 adversarial e2e rejects inflator.
- **Status:** Fixed. Residual: layout constants (`redeemLen`/`backerOff`) must match silverc (unit-tested).

---

## High

### H-1 — Claim vs reclaim after deadline *(FIXED — Stag Hunt grace)*
- SilverScript supports only `tx.time >=`. Cannot disable `claim` after deadline.
- **Fix (pt277u):** On-chain temporal is `refundOpensAt = deadline + grace` (default 3d). Owner may claim anytime sum ≥ goal. Backer reclaim is permissionless only after refunds open. Owner must claim within the grace window once the goal is met.
- **Status:** Fixed. Residual trust: owner liveness during grace if goal met.

### H-2 — `/sign` phishing / wrong destination if AI passes bad params *(PARTIALLY MITIGATED)*
- Attacker (or confused model) could prepare a fund to an unexpected P2SH.
- **Mitigation:** `expectedP2shAddress` check in prepare + browser build; campaign pledge API re-resolves with expected P2SH.
- **Status:** Mitigated for prepared flows; users must still read destination on `/sign`.

### H-3 — Self-host spending wallet key in Worker secret *(OPERATIONAL)*
- Compromise of Cloudflare account / leaked secret = theft of spending wallet funds.
- **Mitigation:** Caps, withdraw-only to locked main address, public demo refuses spending wallet, `MCP_PUBLIC` gate.
- **Status:** By design; docs must stress tiny balances + Cloudflare 2FA.

## Medium

### M-1 — Campaign tracker only sees registered pledges *(OPEN)*
- Status sums UTXOs for pledges registered via MCP/API, not a global chain scan.
- **Impact:** Off-page direct sends to a derived address may not appear until registered.
- **Mitigation:** One-tap pledge registers first; `l1_aon_add_pledge` accepts `campaignPageId`.
- **Status:** Open (product limit). Document clearly.

### M-2 — Sign session store lacks CSRF binding to origin beyond URL secrecy *(OPEN)*
- Knowledge of `/sign/<32-hex>` is the capability.
- **Mitigation:** Short TTL (15m), no keys in session, rate limits on Worker.
- **Status:** Open; acceptable for tap-to-approve if links are not posted publicly before use.

### M-3 — AoN reclaim fee / compute mass *(FIXED for spend path)*
- Hardcoded min fee + `lockTimeMs` + higher `sigOpCount` needed for heavy scripts.
- **Status:** Fixed in contract (`minFee` floor) + `l1-build.js` lockTime + campaign reclaim `sigOpCount: 10`.

### M-4 — Prompt injection via tool results into agent behavior *(OPEN)*
- Malicious page/email content could steer a connected agent.
- **Mitigation:** Safety banner; public demo keyless; spending wallet allowlist.
- **Status:** Open (inherent to agent MCP). Prefer Always-allow only on self-host with locked withdraw address.

### M-5 — Crowdfund discoverability failure led agents to “compile locally” *(FIXED)*
- Claude used `l1_derive_p2sh` / tipjar paths instead of `l1_aon_create_campaign`.
- **Fix:** MCP instructions + tool descriptions + derive redirects to `l1_aon_create_campaign`.
- **Status:** Fixed this cycle.

## Low

### L-1 — Contract page HTML historically showed warning chrome on mainnet *(N/A for campaign)*
- Campaign page intentionally has **no warning flags** per product (pt267u).
- Tipjar `/page/` still may show unaudited banner on mainnet — keep for high-stakes templates.

### L-2 — REST failover list is short by default *(OPEN)*
- Default `api-tn10.kaspa.org` only; self-hosters should set `KASPA_REST_URLS`.
- **Status:** Open / documented.

### L-3 — No SRI on `/kaspa-wasm` assets *(OPEN)*
- Assets served same-origin from Worker `[assets]`; CSP on `/sign` restricts connect-src.
- **Status:** Open; recommend Subresource Integrity or pinned asset hashes in a follow-up.

### L-4 — `l1_check_session` trusts client-reported txid via explorer callback *(OPEN)*
- `/api/sign/:id/explorer?txid=` now persists `submittedTxid` without verifying inclusion.
- **Mitigation:** Optional follow-up: `l1_confirm_tx` already exists for inclusion checks — agents should call it after `submitted`.
- **Status:** Open (Low); document agent playbook.

### L-5 — Integer encoding width for goal/deadline rebind *(MITIGATED)*
- Rebind refuses width mismatch vs demo artifact.
- **Status:** Mitigated by throw; UX should pick goals in supported magnitude.
